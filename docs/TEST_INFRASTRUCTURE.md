# FOCUS-004: тестовая база и предложение по запуску

Это описание. Тесты и конфигурация в репозиторий в рамках FOCUS-004 не добавлялись, приложение не менялось.

## 1. Что есть сейчас
- Среда: Python + Playwright + Chromium (в рабочей области Claude), файл `tlib.py` (запуск страницы с поддельным адресом `http://kassa.test/`, подмена часов `2026-10-13T12:00`, начальные данные, начальная вкладка «Финансы», журнал развёрнут).
- 55 файлов `test*.py`; это **не 55 автоматических тестов**. Разбивка (подробно в `FEATURE_COVERAGE.md`, раздел 5): 3 файла с `assert` (работают `test1`, `test5`; `test2` не воспроизводим), 49 сценарных скриптов без проверок результата (34 работают, 12 подтверждённо устарели, 3 падают с неустановленной причиной: `test8`, `test11`, `test17`), 3 вспомогательных файла (`test4`, `test10`, `test33`). Отдельно: `audit.py` (вёрстка 24 окон на 8 размерах, без `assert`), `tlib.py`, снимки экрана `shot*.py`, `setshot*.py`, `t9.py`, `t50.py`, `tap.py` и 30 скриптов правок `patch*.py` (не тесты).
- Файлы лежат только в рабочей области сессии, **в репозитории их нет**. Если рабочая область пропадёт, тесты пропадут.
- Единого запуска и итогового отчёта нет. Сценарии печатают результат, а `assert` есть только в `test1`, `test2`, `test5`; сценарии без `assert` не считаются автоматическими проверками.
- Шум: сообщение `ERR_TUNNEL_CONNECTION_FAILED` в консоли (шрифты Google недоступны из изолированной среды), к приложению отношения не имеет.

## 2. Проблемы
1. Тесты не в репозитории.
2. 18 из 55 файлов завершаются с ошибкой: 12 устарели (подтверждено), 3 — причина не установлена (`test8`, `test11`, `test17`), `test2` не воспроизводим (внешний файл), `test4` и `test10` не являются тестами. Устаревшими без подтверждения ничего не объявлено. `test8` и `test9` игнорируют параметр пути `KH`.
3. Проверок результата почти нет: сценарии ловят только исключения.
4. Нет данных «золотого эталона»: нет контрольной резервной копии, на которой проверяются расчёты (лимит, прогноз, бюджет, кредит).
5. Шрифты Google в среде проверки не грузятся.

## 3. Предложение: единый воспроизводимый порядок

### Структура в репозитории (отдельная задача после согласования)
```
tests/
  README.md          как запускать
  lib.py             из tlib.py (часы, начальные данные, подмена адреса)
  fixtures/          контрольные копии и данные
  e2e/               сценарии, переименованные по функциям (feature_F15_daily_limit.py …)
  legacy/            устаревшие сценарии, сохранённые как есть (не удаляются)
  run_all.sh         единый запуск
```

### Единый запуск (`run_all.sh`, эскиз)
1. Взять `index.html` из рабочей папки (параметр пути).
2. Запустить сценарии параллельно по 4–6 штук с таймаутом 120 секунд на сценарий.
3. Результат каждого записать в `tests/out/<имя>.out` с кодом выхода.
4. Итог: таблица «имя — OK/FAIL — первая ошибка», код возврата 0 только если не упало ничего из каталога `e2e/`.
5. Шрифты Google подменять заглушкой (маршрут `fonts.*` → пустой ответ), чтобы консоль была чистой.
6. Отдельный шаг `audit.py`: вёрстка всех окон на 8 размерах (нулевое число проблем).

### Правила
- Каждый сценарий проверяет результат через `assert` (число, текст, состояние хранилища), а не печатает.
- Каждая функция из каталога имеет хотя бы один сценарий; таблица покрытия обновляется вместе с тестами.
- Деньги (F-15 лимит, F-17 итог месяца, F-22/23 кредит, F-26 бюджет, F-28 машина времени) проверяются на фиксированных данных с ожидаемыми числами, посчитанными независимо.
- Устаревшие сценарии не удаляются, а переносятся в `legacy/` с пометкой причины, затем чинятся по одному.
- Обязательно для каждой задачи, меняющей данные: круг «создать копию → очистить → восстановить → сравнить».

## 4. Порядок ремонта (предложение)
1. Положить текущие сценарии и `tlib.py` в репозиторий как есть (`tests/legacy/`).
2. Написать `run_all.sh` и получить «зелёный» базовый отчёт на baseline.
3. Починить 12 подтверждённо устаревших сценариев и продиагностировать 3 непонятных по списку (новые селекторы, переключение вкладок и страниц настроек).
4. Добавить сценарии с assert для функций без покрытия, начиная с F-15, F-17, F-10, F-32, F-27.
5. Только после этого начинать рефакторинг (FOCUS-005 и далее).
