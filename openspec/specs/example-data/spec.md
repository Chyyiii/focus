
# Примеры данных и первый запуск

Источник существующего поведения: код &#40;`loadExamples`, `clearEx`, фильтры `!t.example`&#41;\. Каталог: F\-36\. Режим разработчика &#40;идентификаторы `dx…`&#41; описан отдельно в `appearance-pwa` и должен остаться без изменений\.

## Requirements

### Requirement: Выбор сценария при первом запуске

Если приложение открыто впервые и в нём ещё нет пользовательских данных, приложение SHALL показывать приветственный экран FOCUS с вопросом «Как хочешь начать?» и двумя вариантами:

- «Посмотреть FOCUS на примере»;
- «Начать с нуля»\.

Экран SHALL показываться только до первого выбора пользователя\. Выбор SHALL сохраняться отдельно от демонстрационных записей, чтобы перезапуск приложения не приводил к повторному показу экрана\.

#### Scenario: Первый запуск

- **WHEN** приложение запускается без ранее сохранённого выбора первого запуска и без пользовательских данных
- **THEN** приложение показывает приветственный экран с двумя вариантами начала работы
- **AND** демонстрационные данные ещё не добавляются автоматически

#### Scenario: Выбор демонстрации

- **WHEN** пользователь выбирает «Посмотреть FOCUS на примере»
- **THEN** приложение добавляет демонстрационные записи с признаком `example: true` через существующий механизм `loadExamples()`
- **AND** сохраняет выбор первого запуска
- **AND** открывает приложение с демонстрационными данными

#### Scenario: Начать с нуля

- **WHEN** пользователь выбирает «Начать с нуля»
- **THEN** приложение не добавляет демонстрационные данные
- **AND** сохраняет выбор первого запуска
- **AND** открывает приложение с пустым журналом

#### Scenario: Повторный запуск

- **WHEN** пользователь уже выбрал один из вариантов первого запуска
- **THEN** приветственный экран повторно не показывается при последующих запусках

#### Scenario: Существующие данные

- **WHEN** приложение обновлено до версии с приветственным экраном и на устройстве уже есть пользовательские данные
- **THEN** приложение не показывает приветственный экран поверх существующих данных
- **AND** не добавляет демонстрационные данные автоматически

### Requirement: Загрузка примеров

При выборе «Посмотреть FOCUS на примере» приложение SHALL использовать существующий механизм `loadExamples()`\. Он добавляет 10 записей: 2 дохода &#40;«Зарплата», «Подработка»&#41; и 8 расходов в категориях «Жильё», «Продукты» &#40;3 записи&#41;, «Транспорт», «Кафе и рестораны», «Связь», «Здоровье» с датами от 0 до 8 дней назад в текущем месяце &#40;не раньше 1\-го числа&#41;\. Каждая запись получает признак `example: true`, просмотр переключается на текущий месяц\.

### Requirement: Пометка в журнале

Запись\-пример SHALL отображаться в журнале с пометкой «пример»\.

### Requirement: Удаление примеров

Если в данных есть хотя бы одна запись\-пример, приложение SHALL показывать в подвале кнопку «Убрать примеры»\. Нажатие SHALL удалять только записи с признаком `example`, не затрагивая пользовательские записи\.

### Requirement: Исключение примеров из расчётов и файлов

Записи\-примеры MUST NOT учитываться в: файле резервной копии; экспорте в CSV; сверке дублей при импорте CSV; сравнении при восстановлении копии с заменой записей; оценках рекомендуемого бюджета и машины времени; условии напоминания о резервной копии &#40;нужна хотя бы одна реальная запись&#41;; остатках счетов; показателе «Баланс» и графике 30 дней на экране «Сегодня» &#40;`homeBal`, `homeTrend`&#41;\.

Записи\-примеры SHALL учитываться в остатке месяца, итогах, дневном лимите и журнале раздела «Финансы» &#40;общая агрегация `agg()` не исключает их&#41;\.

NEEDS FOUNDER CLARIFICATION: «Баланс» на экране «Сегодня» не включает примеры &#40;при выключенных счетах&#41;, а остаток месяца в «Финансах» включает\. Подтвердить, что так задумано\.

### Requirement: Утрата признака при правке

Если пользователь редактирует запись\-пример, признак `example` SHALL сниматься, и запись становится обычной &#40;код `delete t.example` при правке записи и записи копилки&#41;\.

### Requirement: Ограничение

Загрузка примеров MUST NOT выполняться повторно через пустой журнал, пока в журнале есть записи\. Кнопка «Загрузить примеры» в пустом журнале может оставаться доступной как ручной способ загрузки после первого запуска, но приветственный экран первого запуска не должен появляться повторно\.

### Requirement: Режим разработчика

Существующий режим разработчика SHALL остаться без изменений: добавление и удаление демонстрационных данных с идентификаторами `dx…`, состав этих данных и остальные инструменты режима разработчика сохраняются\.

#### Scenario: Независимость режимов

- **WHEN** пользователь выбирает демонстрацию при первом запуске
- **THEN** это не включает и не изменяет режим разработчика
- **AND** действия режима разработчика не меняют сохранённый выбор сценария первого запуска

### Requirement: Исключение примеров из резервных копий

Демонстрационные записи с признаком `example` MUST NOT попадать в файл резервной копии\. Данные режима разработчика с идентификаторами `dx…` MUST NOT попадать в резервную копию в соответствии со спецификацией `backup-security`\.
