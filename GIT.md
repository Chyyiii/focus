# Работа с git в проекте FOCUS

Основная ветка: `main`. Это то, что видят пользователи на GitHub Pages.

## Правила
1. **Одна задача = одна ветка.** Имя по номеру задачи: `focus-002-data-protection`. Совпадает с названием папки в `openspec/changes/`.
2. **В `main` напрямую ничего не пушится.** Изменения попадают туда через pull request после проверки по `tasks.md`.
3. **Сообщения коммитов:** `FOCUS-002: короткое описание`. Не «Add files via upload».
4. **Релиз:** тег с версией (`v110`) и поднятый номер кэша в `sw.js` (`kassa-v29`) в одном коммите.
5. **Перед крупным изменением** создаётся тег или ветка-копия `backup/<дата>-<что>`. Откат: вернуться к тегу.
6. **Данные пользователей не лежат в репозитории.** Резервные копии (`kassa-*.json`) в git не добавляются.

## Пока нет доступа на запись для Claude
Правила действуют вручную через сайт GitHub:
- Ветка: кнопка с названием ветки → «New branch».
- Загрузка файлов: «Add file → Upload files», внизу выбрать «Create a new branch» и дать имя по правилу 1.
- Слияние: «Compare & pull request» → «Merge pull request».
- Тег: «Releases → Draft a new release» → ввести тег (`v110`) → «Publish».

## Откат
Если новая версия сломалась: «Releases» → предыдущий тег → скопировать оттуда `index.html` и `sw.js` (с более высоким номером кэша, иначе сервис-воркер не обновит файлы) → закоммитить в `main`.
